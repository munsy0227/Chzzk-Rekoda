# 복구 중 후속 조각 보존과 해외 녹화 누락 개선

확인일: 2026-10-11. 사용자가 구현을 명시적으로 승인한 범위다. 구현 근거와 실제 검사 결과는 [작업 기록](../worklogs/2026-10-11-followup-segment-buffer.md)을 따른다.

## 승인한 동작

- 이미 조회한 전체 조각 주소와 PART·방송 시각·불연속 번호를 보존한다. 목록에서 사라졌다는 이유로 알려진 주소를 버리지 않는다.
- 순서대로 출력하는 작업과 목록 조회·후속 수신을 분리한다. 후속 수신에 한 요청 슬롯을 예약하고 총 미디어 요청은 `2 × stream_segment_threads` 이내로 유지한다.
- 검증된 전체 조각과 초기화 데이터를 디스크에 임시 보관한다. 채널별 가장 이른 미출력 위치에서 120초 또는 256MiB까지 보관하며, 쓰는 중인 임시 파일과 메타데이터도 용량에 포함한다. 먼저 확보한 이른 조각을 보존하고 한도가 차도 목록 조회를 계속한다. 저장 실패 시 경고 후 직접 수신을 사용한다.
- 녹화 관리자가 저장 폴더 아래 비공개 임시 디렉터리를 소유하고 내부 `--chzzk-buffer-dir` 인수로 자식에게 전달한다. 같은 방송·화질의 재시작에서 재사용하고 방송 변경·정상 종료·작업 취소 때 정리한다. 강제 종료 후 영구 복원은 구현하지 않는다.
- 필요한 위치의 보관 데이터·알려진 주소를 먼저 사용하고 한국 현재·과거 및 검증된 Akamai 경로를 시도한다. 기존 90초 기한, 초기화·불연속 검사, 중복 방지, 실제 출력 후 checkpoint 정책을 유지한다. 만료 시 가장 이른 유효 후속 조각을 새 파일에서 출력하고 영구 누락 길이만 공백으로 기록한다.
- 버전 1 `recovery_snapshot`에 실행 시각, 실제 조회 시각·소요 시간·결과, CDN/현재·과거 역할, 목록 범위, 필요한 위치, 보관 개수·용량을 기록한다. 시작·완료·전환 및 복구 중 5초 간격의 진단을 사용하고 URL·쿠키·원문 예외는 기록하지 않는다. 같은 CDN의 대체 경로와 다른 CDN의 예비 경로를 다섯 언어로 구분한다.
- 보고서 시작 행에 실행 소스의 SHA-256을 추가하되 기존 보고서와 공백·중복·미해결 전환·불완전 증거 실패 기준은 유지한다.

## 검증과 제외 범위

목록에서 사라진 주소의 복구, 출력 대기 중 후속 수신, 자식 재시작 후 보관 조각 출력, 영구 누락의 정확한 길이, 시간·용량 한도, 디스크 실패, 손상 데이터, 방송·화질·초기화 변경 및 중지 중 수신을 검증한다. 실제 FFmpeg 프레임·음성·PTS 검사도 수행한다.

GitHub Actions의 5분 분할과 영상 정리는 유지한다. 국내 VPS/해외 실방송 장기 검증은 후속 작업이다. 구현·로컬 검사 완료만으로 해외 무손실을 선언하지 않는다. 커밋·push·원격 테스트 실행은 별도 요청에 따른다.
