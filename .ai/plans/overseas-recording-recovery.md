# 해외 녹화 중단 복구와 종료 후 연속성 판정

작성·구현 확인: 2026-10-11. `log2.log` 분석 후 사용자가 GitHub Actions를 해외 녹화 테스트로 구분하고 이 계획의 구현을 승인했다. 한국 장기 녹화는 사용자가 별도로 수행하고 로그를 제공한다. 실제 검증 결과는 [작업 기록](../worklogs/2026-10-11-overseas-recording-recovery.md)에 있다.

## 승인된 범위와 구현

- 검증된 전체 조각을 실제 출력 버퍼에 쓴 뒤 `checkpoint`로 시작·끝 시각을 전달한다. 다음 조각을 모르는 무진행 중단도 마지막 정상 출력 끝을 새 파일의 재개 위치로 보존한다. 시작 위치 선택만으로 커서를 지우지 않는다.
- 목록 요청 실패, 복구 대기, 파일 전환과 실제 공백을 구분한다. 같은 출력 중단의 재시도·Streamlink 재실행은 90초 기한을 공유하며, 새 미디어 출력에 성공할 때만 다음 복구 예산을 허용한다.
- 새 파일에서는 현재·최근 최대 1시간 과거 후보의 정확한 재개 위치를 먼저 검증한다. 기한이 만료되면 해당 위치를 한 번 확인한 뒤 검증 가능한 가장 이른 후속 조각을 선택한다. 후속 조각이 없으면 커서를 유지하며 기다리고 중지에 응답한다. 일반 init/discontinuity 전환의 정확한 재개 조건은 유지한다.
- 후속 조각의 실제 출력 이후에만 재개 위치부터 해당 조각 시작까지를 공백으로 알린다. 복구 대기나 정상 파일 분할·방송 종료·사용자 중지 자체를 공백으로 세지 않는다.
- 기존 버전 1 제어 프로토콜에 `checkpoint`와 선택적 `recovery_deadline`을 추가한다. 필드 허용 목록과 시각 검증을 적용하며 원문 URL·쿠키·예외 메시지를 보고서에 전달하지 않는다. DNS/TLS/연결/시간 초과/파싱 진단은 예외 유형만으로 분류한다.
- 선택적 `--continuity-report PATH`는 조각·복구·전환 증거를 NDJSON에 저장한다. 정상 정리 완료 여부를 footer로 남기며 기록 실패를 정상 완료로 숨기지 않는다. 설정·로그 파일과 같은 경로는 거부한다.
- GitHub Actions는 복구 경고가 있어도 요청한 시간까지 녹화를 계속한 뒤 연속성을 판정한다. 확인된 공백, 미해결 전환, 날짜 없는 출력, 중복, 누락·손상된 보고서는 실패 조건이다. 기존 무출력 감시·FFmpeg 실패 조건도 유지한다. 원본 보고서와 요약 JSON은 실패 시에도 업로드한다. 코덱 테스트에도 같은 기준을 적용한다.
- 테스트의 5분 분할 및 오래된 영상 삭제는 유지한다. 연속성 증거는 삭제 대상에서 제외한다. 런타임 안내 및 README는 5개 언어에 반영한다.

## 검증 경계

로컬 HTTP 장애 주입, 실제 Streamlink 8.6.2·FFmpeg 프레임/음성/PTS 검사, 종료 후 판정 스크립트 검증을 수행한다. 보고서의 공백은 검증된 조각의 방송 시각을 비교한 결과이며 전체 방송 디코딩 검사와 구분한다. 해외 5시간 재실행, 한국 장기 실방송, Windows/macOS, 실제 회원 전용 방송은 별도 확인이 필요하다. 커밋·push·원격 Actions 실행 및 강제 종료 후 커서 영구 복원은 이번 범위 밖이다.
