# Qt GUI 설계

작성: 2026-09-06.
갱신: 2026-09-08.
상태: 리본 UI, 지연 도움말, CLI/GUI 병행, 채널 프로필 이미지 및 현재 녹화 미리보기를 실제 구현했다. 아래 내용은 설계 기준이며 현재 구조와 확인 범위는 [구현 기록](../worklogs/2026-09-08-qt-gui-implementation.md)을 우선 참고한다. 트레이, 실행 파일 패키징 및 플랫폼별 실환경 검증은 후속 범위다.

## 확정 요구사항

- 리본 UI 형태로 구성한다.
- 깔끔하며 처음 사용하는 사람도 주요 기능을 쉽게 찾고 이해할 수 있어야 한다.
- 설정 위에 잠시 마우스 포인터를 올리면 설명을 표시한다.
- CLI와 GUI를 모두 사용할 수 있는 구조를 유지한다.
- 기존 CLI의 모든 설정을 제공한다. 초기 시안 완성 이후 사용자가 실제 구현을 요청했으며, 필드별 범위는 [설정 대응표](gui-settings-coverage.md)를 따른다.

## 권장 방향

- Python 코드를 활용하는 PySide6 + Qt Widgets로 시작한다. 채널 목록, 설정 폼, 로그 중심의 데스크톱 도구에 맞춰 구성한다.
- 기존 CLI 실행 경로를 유지하고 GUI를 추가 진입점으로 제공한다. Qt는 선택 의존성으로 두어 CLI 환경에서 강제 설치되지 않게 한다.
- GUI는 Qt 이벤트 루프를 사용하고 녹화기는 별도 프로세스에서 기존 asyncio 루프를 사용한다. GUI가 `QProcess`로 녹화기를 실행하고 명령/상태를 주고받게 한다.
- 브랜드 중심 화면, 풍부한 전환 효과, 터치 조작이 핵심 요구가 되면 Qt Quick/QML을 대안으로 검토한다.

## 리본 화면 구성

- 상단은 프로그램 이름과 상태, 리본 탭, 선택한 탭의 명령 그룹 순서로 배치한다. 중앙 채널 목록은 리본 탭을 바꿔도 유지한다.
- `홈`: 자동 녹화 시작, 안전한 중지, 채널 추가, 저장 폴더 열기. 자주 쓰는 작업을 가장 먼저 표시한다.
- `채널`: 검색/ID 추가, 활성화/비활성화, 삭제, 저장 경로. 삭제는 등록 해제이며 녹화 파일 삭제와 분리한다.
- `녹화 설정`: 파일 형식, 파일 분할, 방송 확인 간격을 먼저 보여 주고 인코더/비트레이트/DNS/쿠키는 별도 고급 설정에서 제공한다.
- `도움말`: 처음 사용하기, 선택 설정의 설명, 로그 확인.
- 주요 버튼은 아이콘과 텍스트를 함께 표시한다. 최소한의 강조색을 사용하고 상태는 색뿐 아니라 문구로도 구분한다.
- 채널이 없으면 `채널 추가 → 저장 위치 확인 → 자동 녹화 시작`을 안내한다. 녹화 중에는 현재 파일을 저장하고 종료하는 과정을 화면에 표시한다.
- 창이 좁아지면 리본 그룹을 접거나 보조 메뉴로 옮긴다. 고해상도 배율, 키보드 이동, 긴 번역 문자열에서도 버튼이 잘리지 않게 한다.

## 설정 도움말 동작

- 권장 최초 지연은 약 700ms다. 포인터가 다른 설정으로 이동하면 예약된 설명을 취소하고 새 설정 설명을 표시한다.
- 설명은 설정 이름, 쉬운 기능 설명, 권장값/예시, 실제 적용 시점을 담는다. 실제 코드에서 확인되지 않은 즉시 적용을 약속하지 않는다.
- 예: `파일 분할 — 긴 방송을 정해진 간격으로 나눠 저장합니다. 60분이면 약 1시간마다 새 파일을 만듭니다. 0분은 분할하지 않습니다.`
- 화면 밖으로 잘리지 않도록 설명 위치를 보정하고, 클릭/탭 전환/포커스 이동/Esc 시 적절히 닫는다. 비활성 설정에도 사용할 수 없는 이유를 제공한다.
- 키보드 포커스에서도 같은 설명을 제공하고 `F1` 또는 설명 버튼으로 고정된 도움말을 열 수 있게 한다. 중요한 저장/중지 영향은 툴팁에만 숨기지 않는다.
- 설명 문구는 `i18n.py`에 5개 언어로 관리하며 라벨, 검증 범위, 기본값, 도움말을 동일한 설정 정의에서 참조한다.
- Qt 구현은 `QToolTip`과 `QStyle.SH_ToolTip_WakeUpDelay`를 우선 검토한다. 필요하면 `QProxyStyle` 또는 단발 타이머로 지연과 포커스 동작을 제어한다.

## 화면별 기능 범위

| 화면 | 첫 버전 기능 |
| --- | --- |
| 녹화 현황 | 채널별 대기/녹화/재시도/정리 중/오류 상태, 녹화 시간, 용량, 속도, 자동 녹화 활성화 및 중지 |
| 채널 관리 | 이름 검색 또는 ID로 추가, 중복 확인, 활성화/비활성화, 저장 폴더 선택 및 열기 |
| 설정 | 저장 형식과 분할 간격, 재조회 간격, HEVC/AV1, 쿠키, DNS, 언어 |
| 로그 | 전체/채널별 로그와 오류 필터, 복사, 최근 로그 수 제한 |

전체 설정 시안에는 기본 녹화, HEVC/AV1, 로그인, 네트워크, 언어/로그, 채널 관리를 모두 포함한다.
실제 Qt 연결 단계에서는 전체 설정을 제공하는 것을 완료 조건으로 삼고, 녹화기 명령/상태 연결과 단계적으로 검증한다. 트레이 및 알림, 플랫폼별 실행 파일 패키징은 이후 확장 항목이다.
기본 화면은 채널 상태를 중심에 배치하고 고급 옵션은 별도 설정 화면에 둔다.

## 코드 연결 방법

아래 경계를 실제 공용 모듈 및 GUI 계층으로 구현했다.

- `config_store.py`: 기본값, 정규화, 로드/저장, 기존 설정 마이그레이션을 공용화한다. UI 출력과 `SystemExit` 처리는 호출하는 CLI/GUI에서 맡긴다.
- `channel_service.py`: 채널 검색/조회 로직을 분리한다. GUI에서는 네트워크 요청과 인코더 probe를 UI 스레드에서 실행하지 않는다.
- `settings.py`: 공용 함수를 사용하는 CLI로 유지하고 메뉴를 `main()`과 실행 가드 안으로 옮긴다.
- `chzzk_record.py`: 기존 녹화 흐름을 재사용하며 Rich 표시 없이 실행하는 모드와 명령/이벤트 연결 지점을 추가한다. 직접 import 부수 효과를 먼저 확인한다.
- `gui/`: 창, 채널 모델, 설정 화면, 녹화 프로세스 연결 코드를 나눈다. 공유 코어는 PySide6에 의존하지 않게 한다.
- `chzzk_gui.py`: GUI 실행 진입점으로 사용한다.

CLI와 GUI는 공용 설정/채널/녹화 기능을 호출하는 별도 입구로 둔다. GUI에서 CLI 메뉴의 `input()`을 자동 입력하거나 번역된 콘솔 화면을 해석하는 방식은 사용하지 않는다.
일반 CLI 실행에는 Qt를 설치할 필요가 없도록 GUI 의존성을 선택 항목으로 제공한다.
초기 녹화 엔진은 기존 `chzzk_record.py` 흐름을 활용하고, 점진적으로 화면 표시와 설정 처리만 분리한다. 새 GUI를 이유로 인코딩/재시도/정리 로직을 복제하지 않는다.
동일 채널을 CLI와 GUI에서 중복 녹화하지 않게 실행 소유권을 확인한다. 두 인터페이스 지원이 동일 설정에 대한 무제한 동시 쓰기를 의미하지는 않는다.

## 녹화 상태와 종료 계약

- 파이프에서 JSON 한 줄씩 명령과 이벤트를 주고받는 방식을 우선 검토한다. 버전, 이벤트 종류, 채널 ID를 포함하고 번역된 터미널 문자열을 상태 판정에 사용하지 않는다.
- 녹화기 stdout은 구조화 이벤트용으로 사용하고 일반 진단 출력은 stderr로 보낸다. UTF-8, 분할 수신 버퍼, 최대 메시지 크기, 출력 flush를 명시한다.
- 상태 갱신 주기와 로그 큐 크기를 제한하고, GUI 수신이 느릴 때 녹화 파이프가 막히지 않도록 한다. 기존 로그 큐의 상한과 종료 로그 처리 동작을 보존한다.
- GUI에서 중지 명령을 보내면 녹화기는 기존 `shutdown_event`와 파일 정리 경로를 사용한다. FFmpeg 정리와 종료 완료 이벤트를 확인한 후 화면에 완료를 표시한다.
- Windows에서 `QProcess.terminate()`만으로 정상 종료를 보장할 수 없으므로 명시적인 중지 명령을 기본 경로로 사용한다. 강제 종료는 정상 종료 제한 시간 이후의 최후 수단으로 둔다.
- 창 닫기는 첫 버전에서 안전 종료로 처리하는 안을 우선 제안한다. 트레이 기능을 추가할 때 창 숨기기와 프로그램 종료를 구분한다.
- GUI 비정상 종료/입력 파이프 단절 시 녹화기의 안전 종료 정책과 Streamlink/FFmpeg 자식 프로세스 정리를 구현하고 검증한다.
- 중복 GUI/CLI 녹화 실행 방지를 위한 실행 잠금과, 동시에 설정을 수정할 때의 충돌 감지를 검토한다.
- 현재 설정 재조회만으로 진행 중 녹화에 모든 옵션이 즉시 반영된다고 가정하지 않는다. 항목별로 즉시 적용/다음 녹화 적용/재시작 필요 시점을 확인하고 UI에 표시한다.

## 구현 순서와 완료 기준

1. **공용 설정 처리 분리**: 기존 `config.json`과 CLI 동작을 유지하고, import만으로 파일 변경이나 메뉴 실행이 발생하지 않는지 확인한다. 손상 설정 보존, 저장 실패, 기존 필드 유지, 마지막 유효 설정 유지 경로를 검증한다.
2. **최소 GUI와 녹화 연결**: 채널 목록과 설정, 시작/중지, 상태/로그를 실제 녹화기에 연결한다. 모의 이벤트 확인과 실제 짧은 녹화의 시작/중지/결과 파일 probe를 구분해 검증한다.
3. **사용성 및 배포**: 5개 언어, 고급 설정, 로그인, 트레이/알림을 추가하고 Windows/macOS/Linux에서 각각 검증한 범위를 기록한다. 실행 파일 패키징은 녹화 동작이 안정된 후 진행한다.

문법 컴파일 및 `git diff --check` 외에도 설정 손상, 녹화 중 GUI 종료, 녹화기 비정상 종료, 로그 폭주, 자식 프로세스 잔존 여부를 확인한다.
수행한 검증과 미검증 사항은 구현 기록에 남긴다. 제안한 모든 확장 항목까지 검증했다는 뜻은 아니다.

## 확인한 공식 자료

- [Qt for Python](https://doc.qt.io/qtforpython-6/): PySide6는 Qt의 공식 Python 바인딩이다.
- [Qt, QML, Widgets 차이](https://doc.qt.io/qtforpython-6/faq/whatisqt.html): 화면 기술 선택 시 참고.
- [QProcess](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QProcess.html): 비동기 프로세스 출력 신호와 Windows 종료 동작을 확인했다.
- [QToolTip](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QToolTip.html): 위젯 도움말, 서식 있는 설명 및 표시 위치 처리를 확인했다.
- [QStyle](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QStyle.html): `SH_ToolTip_WakeUpDelay`로 도움말 표시 지연을 지정할 수 있다.
