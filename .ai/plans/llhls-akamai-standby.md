# 한국 CDN 우선 LL-HLS와 Akamai 예비 복구

승인·구현 확인: 2026-10-11, Asia/Seoul. 사용자 승인 계획과 구현 중 추가 지시를 반영한다. 검증 결과는 [작업 기록](../worklogs/2026-10-11-llhls-akamai-standby.md)에 있다.

## 확정 동작

- 기존 한국 CDN을 우선하고, 같은 CDN에서는 LL-HLS를 일반 HLS보다 먼저 선택한다. 과거/예비 조회는 주 경로를 바꾸지 않는다. 한국 경로가 없거나 접근할 수 없으면 Akamai를 사용할 수 있다.
- 최초 계획은 API 제공 주소만 쓰는 것이었다. 사용자가 한국 접속으로 돌아온 뒤 **API에 없어도 Akamai를 대입하고 접속을 확인하라**고 추가 지시했다. `nvelop-livecloud.pstatic.net`, `livecloud.pstatic.net`의 HTTPS 현재 주소에 한해 호스트를 `livecloud.akamaized.net`으로 대입한다. 원래 경로·서명·쿼리를 유지하고 같은 후보를 중복 생성하지 않는다. 알 수 없는 호스트, 다른 CDN의 주소 및 과거 주소에는 이 대입을 하지 않는다.
- 녹화 시작과 동시에 예비 확인을 별도 작업으로 실행한다. 대입 후보는 목록·동일 화질·같은 시각/길이/불연속 구간·초기화 일치·실제 미디어 다운로드를 확인한 뒤 준비 완료를 알린다. 모든 대체 출력에도 동일한 검증을 적용한다. 실패한 확인은 주 녹화를 지연시키지 않으며 복구 때 다시 확인한다.
- LL-HLS의 실제 PART URI와 길이를 읽고, 공개된 미완료 묶음의 부분 조각을 미리 받는다. PRELOAD-HINT는 확정 조각으로 사용하지 않는다. 원래 전체 조각 단위로 모두 검증한 뒤 한 번만 출력한다. 부분 조각 수와 길이를 고정하지 않는다.
- 누락·손상·GAP·중복·불완전한 길이·암호화/미지원 부분 묶음은 부분 바이트를 버리고 전체 조각으로 대체한다. 기존 전체 AES-128 복호화는 유지한다. 재시작 위치는 완료된 전체 조각 기준이며 기존 커서 형식을 유지한다.
- 서버가 CAN-BLOCK-RELOAD를 제공하면 `_HLS_msn`/`_HLS_part`를 사용한다. 원래 서명 쿼리를 다시 인코딩하지 않는다. 대기 응답에는 target duration에 따른 별도 읽기 예산을 주며 정상적인 새 조각 대기를 바로 미디어 장애로 판정하지 않는다.
- 복구 순서는 한국 현재 → 한국 과거의 같은 구간 → Akamai다. 주 요청의 기존 2초 hedge/즉시 실패 확인에 이어 한국 후보를 먼저 조회한다. 첫 과거 확인이 2초 안에 끝나지 않거나 한국 후보가 소진되면 Akamai도 확인한다. 목록 중간 누락 복구에도 같은 순서를 적용하며 기존 90초 기한을 공유한다.
- 과거 후보는 실제 목록 끝을 기준으로 최근 최대 1시간만 사용한다. 이 복구가 과거 전체 녹화를 다시 시작하지 않는다. 기존 과거 시작 설정과 방송별 한 번의 적용을 유지한다.
- 방송 ID·화질·시각·길이·초기화·불연속 번호/경계가 맞지 않는 대체는 거부한다. 복구 실패 후 공백 안내와 가장 이른 후속 위치의 파일 전환, 방송 종료/사용자 중지, 권한·DoH·헤더 경로를 유지한다.
- URL 없는 `source` 이벤트는 CDN 종류·실제 수신 방식·예비 상태만 전달한다. 5개 언어 안내와 README를 갱신한다. HTTP/1.1 전송 라이브러리와 의존성은 유지한다.

## 검증 범위

- 기존 검사와 LL 부분 묶음, 한국 과거 우선, 느린 이력 중 Akamai 복구, 예비 실패·성공, 주소 대입/서명 보존, Akamai 단독, 암호화 대체, blocking reload, 초기화·불연속·1시간 경계 및 요청 상한을 검사한다.
- 실제 FFmpeg 결과는 프레임 수와 영상·음성 PTS로 확인한다. 짧은 한국 실방송과 한국 접속에서 Akamai 대입/장애 주입 복구를 확인한다. 해외 VPN 상태의 장시간 재검증과 자연 CDN 장애 해결 여부는 별도로 남긴다.
- HAR 원문, 서명 URL, 쿠키, 대용량 미디어는 저장소에 넣지 않는다. 이번 구현 요청에는 새 커밋·push·PR 생성이 포함되지 않는다.
