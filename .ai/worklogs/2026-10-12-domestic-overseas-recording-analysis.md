## 추가로 발견한 두 문제

### Windows 종료 시 미완성 입력과 음성 패킷 손상

- Windows log.log LF 474,538~474,558에서 2026-10-11 17:35:38.345 UTC에 `control_app_exit` 종료가 요청됐고, 3ms 뒤 `Packet corrupt (stream = 1, ...), dropping it.`와 `partial file`이 기록됐다. KST로는 10월 12일 02:35:38이다.
- FFmpeg는 0, Streamlink는 1로 종료했다. Ubuntu/macOS 및 국내는 Streamlink 130으로 종료했으며 해당 손상 메시지가 없었다.
- `dev:chzzk_record.py`의 종료 경로는 `terminate_process(stream_process)` 후 파이프를 배출하고 FFmpeg 정리를 기다린다. `signal_process_group()`는 POSIX에서는 SIGTERM을 보내지만 Windows에서는 `process.terminate()`를 사용한다. 따라서 Windows에서 쓰는 도중 Streamlink가 종료되어 마지막 fMP4 입력이 잘렸을 가능성이 높다. 시간 순서와 코드에 따른 추론이며 영상 파일로 확정한 원인은 아니다.
- `continuity_report.py`는 Streamlink 출력 checkpoint를 검사한다. `scripts/run_recording_test.py:monitor_recording()`의 FFmpeg 실패 검색은 `Invalid NAL unit size`, `Error applying bitstream filters`, `ffmpeg failed for`만 포함해 이번 `Packet corrupt`/`partial file`을 실패로 잡지 않는다. 따라서 해외 보고 합격만으로 Windows 최종 음성까지 무손실이라고 선언할 수 없다. 실제 해외 영상이 없어 끝부분의 손실 길이나 내용은 측정하지 못했다.
- 다음 개선 후보는 Windows 중지를 완료 조각 경계에서 협력적으로 처리하고, 마지막 파일의 영상·음성 및 FFmpeg 종료 진단을 별도로 검증하는 것이다. 이번 분석에서 구현하지 않았다.

### `buffer_full`이 용량 부족과 이미 출력한 조각을 구분하지 않음

- `buffer_full` snapshot은 Ubuntu 18회, Windows 8회, macOS 10회, 총 36회다. 36회 모두 `buffered_count=0`, `buffered_bytes=0`이며 해당 target 조각은 이미 직전 checkpoint까지 출력된 위치였다.
- `recording_buffer.py:MediaBuffer.can_store()`는 용량/시간 상한뿐 아니라 조각 끝이 `cutoff` 이전인 경우에도 false를 반환한다. `store()`는 모든 경우 `BufferFull`을 발생시키고 `hls_continuity.py:preserve()`는 복구 중 이를 같은 `buffer_full` 결과로 기록한다.
- 이번 36건은 저장 용량 부족의 증거가 아니라 이미 출력한 조각의 뒤늦은 다운로드 결과를 보관하지 않은 경우다. 실제 출력 중복은 없었다. 진단에서 `already_output`과 실제 시간·바이트 상한을 구분하면 다음 분석의 오해를 줄일 수 있다. 이번 분석에서 코드나 이벤트 형식을 변경하지 않았다.

## 해석과 남은 검증

- 이번 국내 영상은 일시적인 수신 지연과 Akamai 대체 수신을 겪고도 제공된 녹화 파일의 영상·음성 시각 연속성을 유지했다. 해외 세 OS도 조각 출력 보고서 기준으로 약 5시간 동안 누락·중복·미해결 전환이 없었다. 개선 코드의 실방송 근거가 추가됐지만 모든 장애의 무손실 보장은 아니다.
- 실방송에서 90초 복구 만료나 프로세스 재시작 인계는 발생하지 않았다. 보관 상한, 디스크 실패, 손상 보관 데이터, 방송·화질·초기화 변경, 영구적으로 없는 조각의 정확한 공백 판정은 이번 제공 자료로 새로 검증하지 않았다. 이전 구현의 자동 검증과 구분한다.
- 사용자가 후속 구현을 요청하면 `dev`의 현재 상태를 다시 확인하고 Windows 종료 문제와 보관 거절 원인 진단부터 검토한다. 해외 최종 영상 검증을 위한 자료 보존 범위도 별도 결정할 수 있다. 이번 분석으로 기존 5분 분할·영상 정리 설정을 바꾸지는 않았다.
