# 사용자 제공 프로그램 아이콘 적용

## 요청과 변경

- 2026-09-10: 사용자가 첨부 아이콘을 프로그램에 적용하도록 요청했다. 첨부는 이름과 달리 1280×1280 JPEG였으며, 그림과 바깥 검은 배경을 유지해 형식/해상도만 변환했다. 이미지 재생성이나 투명 배경 추정은 하지 않았다.
- `assets/chzzk-rekoda.png`는 512×512, `assets/chzzk-rekoda.ico`는 16/20/24/32/40/48/64/96/128/256px를 포함한다. ImageMagick으로 변환했으며 실행 시 ImageMagick은 필요 없다. 원본 첨부는 변경하지 않았다.
- `gui/appearance.py:application_icon()`의 임시 도형 아이콘을 PNG/ICO 로딩으로 바꿨다. QApplication, MainWindow, QSystemTrayIcon의 기존 공용 경로에 적용된다.
- `gui/desktop.py:configure_platform_identity()`는 UI 생성 전 Windows `CHZZK.Rekoda.GUI` AppUserModelID를 지정한다. `chzzk_gui.vbs`는 설치 폴더에 ICO 아이콘을 사용하는 `Chzzk Rekoda.lnk`를 생성/갱신한다. 폴더 이동 후 VBS 재실행 시 경로를 갱신하고, 바로가기 쓰기 실패가 GUI 실행을 막지 않는다. `.lnk`는 `.gitignore`에 추가했다.
- Linux 폴더 실행 파일의 Icon은 `chzzk-rekoda`다. GUI 실행 시 `register_linux_desktop()`이 XDG_DATA_HOME(기본 `~/.local/share`)의 hicolor/512x512/apps 아이콘 및 applications/Chzzk-Rekoda.desktop을 등록한다. 설치된 `.desktop`은 URI로 원본 프로젝트 실행기를 참조해 한글·공백·퍼센트·셸 문자 경로를 보존한다. 같은 내용은 재작성하지 않으며 쓰기 실패가 GUI를 중단시키지 않는다.
- 5개 README에 아이콘/바로가기 사용법을 반영했다. UI에 새 번역 문자열은 추가하지 않았다. 앞선 우클릭 메뉴 번역 키 수정은 그대로 유지한다.

## 검증과 한계

- Qt에서 ICO 10개 프레임, PNG 포함 16~512px 렌더링, 100/150/200% 픽셀 비율, 앱·창·트레이 아이콘의 픽셀 일치를 확인했다. 크기별 미리보기를 직접 시각 점검했다. 결과는 `.gui-validation/app-icon-4dohl04v/icon-sizes.png`이며 실제 OS 창 테두리/트레이의 화면 캡처는 아니다.
- 임시 XDG 폴더에서 Linux 아이콘 테마 조회, 중복 등록 시 수정 시각 유지, desktop-file-validate, 실제 `gio launch`를 통한 한글·공백·`#`·`%`·따옴표·`$()` 경로의 실행, 쓰기 권한 실패 처리를 검증했다. 검증은 사용자 홈의 앱 목록을 변경하지 않았다.
- Windows API 모사로 AppUserModelID 값과 인수/반환 타입을 확인했다. 실제 Windows WSH 바로가기 생성과 작업표시줄 표시, macOS Dock은 이 Linux 환경에서 실행하지 못했다. VBS는 Microsoft WSH 방식과 기존 숨김 실행 흐름을 대조했다.
- Python 문법 컴파일, Ruff E9/F/I 및 포맷, desktop 파일 검사, `git diff --check`를 수행했다. 실제 녹화 로직은 변경하지 않았다. 이번 아이콘/메뉴 수정은 커밋·푸시 전이다.

## 검은 외곽의 투명 처리

- 2026-09-10: 사용자가 아이콘의 검은 부분을 투명하게 바꾸고 다시 적용한 뒤 커밋·푸시하도록 요청했다. 시작 HEAD는 `8e4ad66`이며 기존 개인 녹화 폴더 외에 변경이 없었다.
- 내장 imagegen 편집을 두 번 시도했지만, 실제 알파 대신 체크무늬를 포함한 불투명 RGB PNG가 반환돼 사용하지 않았다. 요청 프롬프트의 핵심은 `Remove ONLY the outer black corner background; output RGBA PNG with true alpha=0 outside the mint silhouette; preserve all interior artwork; no painted checkerboard`였다. API/CLI 모델 호출로 전환하지 않았다.
- 최종 자산은 사용자 원본 JPEG에 ImageMagick으로 외곽 알파를 적용해 만들었다. 네 모서리에서 연결된 검은 영역만 `-alpha set -fuzz 40% -fill none -draw 'color 0,0 floodfill color 1279,0 floodfill color 0,1279 floodfill color 1279,1279 floodfill'`로 제거하고 `-filter Lanczos -resize 512x512 -depth 8 -strip PNG32:`로 저장했다. 필터와 비트 깊이를 명시해 기존 PNG 내부 색을 보존했다. 첫 기본 필터 변환의 내부 색 차이를 발견한 후 이 설정으로 수정했다.
- `assets/chzzk-rekoda.png`와 `.ico`를 교체했다. ICO는 `-define icon:auto-resize=256,128,96,64,48,40,32,24,20,16`으로 만들었다. 실행 코드와 파일 경로는 유지되므로 기존 창/트레이/바로가기에서 새 자산을 읽는다. 폰트·개인 설정·녹화 파일은 변경하지 않았다.
- Qt offscreen 검증 통과: PNG 512×512 RGBA, 완전 투명 픽셀 18,453개, 네 모서리 alpha=0, 부드러운 경계의 부분 투명도, 중앙 384×384 영역의 모든 RGB 값이 이전 PNG와 정확히 일치하고 alpha=255. ICO 10개 크기의 투명도와 16~512px·100/150/200% 배율의 앱/창/트레이 아이콘 일치를 확인했다.
- 임시 XDG 디렉터리에 이전 불투명 아이콘을 심은 뒤 `register_linux_desktop()`으로 새 투명 PNG가 갱신되는지 검증했다. 재등록 시 변경 시각 유지와 desktop-file-validate도 통과했다. 사용자 홈의 앱 목록은 변경하지 않았다.
- 최종 PNG를 흰색/어두운 배경에 합성해 외곽을 시각 점검했다(`.gui-validation/transparent-icon/final-preview.png`). 검증 스크립트나 미리보기는 커밋하지 않는다. Python 실행 코드는 변경하지 않았으며 `git diff --check` 통과. 실제 Windows 작업표시줄/바로가기 및 macOS Dock의 표시는 직접 검증하지 않았다.
