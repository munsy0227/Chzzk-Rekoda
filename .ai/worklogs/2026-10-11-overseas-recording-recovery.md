# 해외 녹화 중단 복구 및 CI 연속성 판정

확인: 2026-10-11. 작업 시작 HEAD `50424e5`, 브랜치 `dev`. 사용자 요청: 분할 녹화 설정을 확인한 뒤 GitHub Actions를 해외 녹화 테스트로 구분하고 제안한 개선 계획을 구현한다. 한국 장기 녹화는 사용자가 별도로 테스트한 후 로그를 제공한다. 승인 범위는 [계획](../plans/overseas-recording-recovery.md), 원본 로그 근거는 [log2 분석](2026-10-11-log2-analysis.md)이다.

## 실제 변경

- `hls_continuity.py:deliver()/fail()/boundary()`에서 검증된 전체 조각 출력의 `checkpoint`를 추가했다. `fail(previous, None)`도 마지막 정상 출력 끝을 보존한다. 출력과 실패 전환을 같은 잠금으로 처리해 오래된 커서로 재시작하지 않도록 했다.
- `ContinuitySource.recovery_limit()/progressed()`가 같은 중단의 90초 기한을 관리한다. `recovery_deadline`을 재실행으로 넘기며, 정상 미디어 출력 성공 때만 기한을 초기화한다. `resume_segments()`는 정확한 커서를 먼저 확인하고 만료 후 가장 이른 검증된 후속 위치로 재개한다. 새 90초 미디어 복구를 반복하지 않으며 후보 확인은 기존 요청 슬롯과 개별 시간 제한을 사용한다. 후속 미디어가 없으면 커서를 유지하고 중지에 응답한다.
- Worker는 무진행/일시 목록 실패 중 현재·과거 후보를 재조회한다. 한국 조회가 지연되면 기존 2초 예산 뒤 Akamai도 확인한다. 과거 목록의 ENDLIST는 전체 방송 종료로 간주하지 않으며, API로 확인한 방송 종료는 대기 중단을 정상 종료 이벤트로 정리한다.
- `gap`은 후속 조각을 실제 출력한 뒤 마지막 정상 출력 끝부터 해당 조각 시작까지로 알린다. 파일 전환 시점의 미확인 중단은 `boundary`로 남긴다. 일반 init/discontinuity의 정확한 resume 조건, 방송 ID/화질/init/미디어 검증은 유지한다.
- `recording_continuity.py:RecordingContinuity`는 checkpoint를 재실행 인수에 연결한다. `start` 선택만으로 커서를 지우지 않고 새 출력 후 갱신한다. 출력 없는 boundary 재시도에는 기존 설정의 재시도 간격을 적용한다. `plugin/chzzk.py:resume_option()`은 선택적 기한을 검증하며 버전 1 프로토콜과 기존 resume 인수를 유지한다.
- `failure_category()`는 예외 유형/중첩 원인만 검사해 DNS/TLS/연결/시간 초과/응답 잘림/파싱을 분류한다. `parse_event()`는 모든 이벤트의 허용 필드만 남겨 URL·쿠키·원문 예외가 보고서에 추가되지 않도록 했다.
- 새 `continuity_report.py`와 CLI `--continuity-report PATH`는 NDJSON 시작/출력/복구/전환/종료 증거를 저장한다. 파일과 로그 경로 충돌을 거부하며 쓰기·정리 실패를 성공으로 반환하지 않는다. 요약은 동일 방송·화질의 출력 시각을 비교하고 중복된 공백 증거는 한 번만 합산한다. 미해결 전환, 날짜 없는 출력, 중복, 누락·손상·불완전 보고서는 실패 조건이다. init/discontinuity의 명시적 시각 초기화와 정상 방송 종료는 별도로 처리한다.
- `scripts/run_long_recording_test.sh`는 녹화 종료 후 요약을 생성한 다음 기존 무출력·FFmpeg 오류 조건과 함께 판정한다. 공백 경고 때문에 중간에 녹화를 끝내지 않는다. 장시간/코덱 workflow는 `if: always()` 업로드에 보고서와 요약을 추가했다. 기존 5분 분할과 15분 초과 영상 정리는 유지하며 JSONL/JSON은 삭제하지 않는다.
- 안내와 README 다섯 언어를 함께 갱신했다. `.ai/KNOWLEDGE.md`의 미수정 제한을 실제 구현 상태로 교체했다. 기존 분석 기록은 당시 근거로 보존했다.

## 검증 결과

- 시작 기준선: 기존 71개 테스트 통과. 최종 `.venv/bin/python -m unittest discover -s tests -v`: **91개 통과, 실패·오류·건너뜀 0**, 54.624초. 로컬 HTTP 서버의 소켓 실행은 승인된 실행 환경에서 수행했다. 잠금파일을 바꾸지 않고 로컬 `.venv`에 잠긴 의존성을 설치했으며 Streamlink는 **8.6.2**, Python은 **3.12.15**, 시스템 FFmpeg는 **n9.0.2**다.
- 새/수정 검증: 다음 조각 없는 stall 커서, 만료 커서의 단발 확인, 실제 누락 한 조각만 건너뛰기, 늦게 나타난 정확한 조각, 후속 없음 대기와 빠른 취소, 일시 목록 오류 후 전체 복구, 방송 종료 시 대기 해소, 새 프로세스에서도 만료 기한 유지, start의 커서 보존, 보고서 필드 허용 목록/쓰기 실패/불완전 증거/중복/공백 합집합 및 5개 언어.
- 실제 녹화 관리자 → Streamlink → FFmpeg 두 파일 전환: 다음 위치를 모르는 stall 뒤 제공된 모든 후속 조각을 복구해 **500 + 500 = 1,000 영상 프레임**을 보존했다. 원본 대비 음성 프레임 차이 2개 이하, 두 파일 경계에서 정규화한 최대 영상 PTS 간격 0.04초 미만·음성 0.06초 미만을 확인했다. 기존 init/discontinuity 전환 및 전체/부분 조각 복구도 통과했다.
- 영구 누락을 주입한 전환은 **500 + 250 = 750 영상 프레임**으로 실제 남은 조각만 보존하고 보고서에 공백 1개, 미해결 전환 0개를 남겼다. 기존 known-next 누락/다운로드 실패 전환 검사도 통과했다. 이는 합성 영상의 직접 검사이며 원본 `log2.log` 영상 검사 결과가 아니다.
- 실제 Bash helper에 모의 녹화기를 연결해 정상/공백/프로세스 상태 7의 세 경우를 검사했다. 녹화 완료 표시와 footer 이후 판정되며 실패에도 원본 JSONL과 요약이 남고 원래 프로세스 오류 상태도 유지한다. CI의 실제 장시간/코덱 실행을 대신한 주장은 아니다.
- 수정 Python 7개 파일 문법 컴파일, `git diff --check`, Bash 문법 검사, 두 CLI의 `--help`를 확인했다. 테스트 로그는 `/tmp/chzzk-recovery-tests.log`에 있으며 개인 설정·서명 URL·쿠키·영상 원문을 저장소에 추가하지 않았다.
- 중간 테스트의 이전 gap 기대값과 정상 2초 polling보다 짧은 0.6초 시험 예산을 실제 의미에 맞게 정정했다. CI 모의 검증의 백그라운드 sleep이 캡처 파이프를 붙잡는 시험 환경 문제는 모의 sleep을 짧게 만들어 해결했다. 최종 검증은 이 변경들을 포함한다.

## 미검증 및 다음 확인

- 최종 버전의 해외 5시간 GitHub Actions 재실행, 한국 장기 실방송, 자연 CDN 장애, Windows/macOS, 회원 전용 방송은 미검증이다. 이번 변경이 과거 로그의 모든 손실이나 실제 서비스 장애를 해결했다고 단정하지 않는다.
- 보고서는 검증된 전체 조각의 방송 시각에 근거한다. 장기 방송의 모든 출력 파일 디코딩·실제 프레임 PTS 검사를 자동으로 대체하지 않으며, 날짜가 없으면 연속성 미확인으로 실패시킨다. 사용자 중지 시 아직 기다리던 조각 자체는 확인된 공백으로 집계하지 않는다.
- 강제 종료 뒤 디스크에서 커서를 영구 복원하는 기능은 추가하지 않았다. 기존 FFmpeg 정리와 완료된 파일 보존을 유지한다. 보고서 쓰기 실패가 발생하면 종료 상태와 불완전 증거로 드러난다.
- 사용자 별도 한국 장기 테스트 로그와 새 Actions 보고서가 도착하면 접속 환경별 결과를 구분해 분석한다. 커밋·push·원격 Actions 실행은 하지 않았다.

## 후속 로컬 커밋 요청

- 사용자가 "우선 커밋해줘."라고 요청했다. 이번 복구 개선, CI 보고서/판정, 기존 테스트 확장, 5개 언어 안내, 분석·계획·프로젝트 기록만 하나의 로컬 커밋으로 묶는다. 원격 push와 Actions 실행은 요청 범위에 없다.
- 커밋 준비 시 변경 범위와 최종 검사 로그(91개 통과), `git diff --check`를 다시 확인했다. 최종 검증 후 실행 코드의 추가 변경은 없으며 이 요청 기록만 덧붙였다.
- 기존 프로젝트 커밋과 같은 `Codex <codex@openai.com>` 작성자·커미터를 이번 커밋에만 적용한다. 개인 설정, 원본 로그, 임시 영상과 실행 환경은 포함하지 않는다. 커밋 후 최근 커밋과 작업 트리 상태를 확인한다.
