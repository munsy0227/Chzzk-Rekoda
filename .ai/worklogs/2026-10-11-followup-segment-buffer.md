# 복구 중 후속 조각 보존 구현

확인일: 2026-10-11. 시작 HEAD는 `b19bc17`의 `dev`다. 사용자는 [후속 조각 보관 계획](../plans/followup-segment-buffer.md)의 구현을 승인했으며 커밋·push·원격 테스트는 별도 요청으로 남겼다. 시작 시 이미 존재한 log2 분석·국내 VPS/해외 비교 문서 변경은 보존했다.

## 변경

- `hls_continuity.py:ContinuitySource.remember()/locate()`는 최근 120초·최대 2,048개 관측 항목을 보존한다. 조각과 PART를 복사하고 해당 조회 목록의 불연속 번호를 계산한다. 모든 실제 목록 소비 지점에 원래 playlist를 명시적으로 전달해 동시 갱신의 영향을 피했다. 주소는 메모리에만 둔다.
- `ChzzkContinuityWriter`는 순서 출력과 별개로 복구 중 0.5초 간격의 목록 조회를 시작한다. 성공적으로 조회한 현재·과거 대체 목록의 후속 조각도 같은 보관 작업으로 전달한다. Akamai 호스트 대입 probe는 검증 전 보관 대상으로 쓰지 않는다. 예비 작업은 primary를 덮어쓰지 않는다.
- 일반 미디어 요청 풀은 `2 × threads - 1`, 보관용 풀은 1이다. 보관 작업은 PART 대신 검증 가능한 전체 조각을 한 번 짧게 요청한다. 전체 미디어 요청 상한은 기존 `2 × threads`다. 목록/API 작업은 별도 풀이다.
- 새 `recording_buffer.py:MediaBuffer`는 검증된 init+media, SHA-256, 방송·화질·시각·불연속 정보를 저장한다. 임시 쓰기→파일 교체로 완성하고 완료된 정상 보관 다운로드는 `BufferedDownload` 파일 참조만 가진다. URL·쿠키·원문 예외는 디스크 메타데이터에 포함하지 않는다.
- 시간 한도는 가장 이른 미출력 위치부터 120초, 용량은 메타데이터 및 쓰기 중 예약을 포함한 256MiB다. 먼저 확보한 데이터를 지우지 않으며 후속 future는 용량이 풀릴 때까지 기다린다. 실제 출력에 필요한 맨 앞 조각은 직접 전달할 수 있다. 한도가 찬 동안에도 목록 조회를 계속한다. 디스크 쓰기 실패는 경고 후 직접 수신으로 전환한다.
- 손상·불완전 데이터는 제거하고 알려진 주소에서 재수신한다. 파일 참조를 얻은 뒤 출력 전에 손상된 경우에도 다시 검증한다. 방송·화질이 다른 메타데이터는 재시작 시 제외하고 초기화·불연속 변경은 기존 파일 전환 규칙으로 처리한다.
- `chzzk_record.py:record_stream()`이 저장 폴더 아래 `.chzzk-buffer-*` 비공개 임시 디렉터리를 소유하고 내부 `--chzzk-buffer-dir`로 전달한다. 같은 방송에서 자식 프로세스만 재시작할 때 디렉터리를 유지한다. 방송 변경·CLOSE·관리 작업 종료/취소에는 정리한다. 생성 실패 시 `-`를 전달해 직접 수신을 사용한다. 독립 Streamlink 실행은 자체 임시 디렉터리를 사용한다.
- `.gitignore`에 `.chzzk-buffer-*/`를 추가해 저장 위치가 저장소 안에 있어도 임시 미디어가 Git 변경에 섞이지 않게 했다.
- 복구는 보관 파일/관측 주소를 먼저 확인하고 기존 한국 현재·과거/Akamai 순서와 90초 기한을 유지한다. 기한 만료 후 보관된 가장 이른 유효 후속 위치를 선택한다. 최신 네트워크 목록도 함께 사용해 보관 조각 뒤의 최신 조각이 빠지는 것을 방지했다. 같은 주소가 여러 후보 목록에 겹칠 때 중복 재시도하지 않는다. 실제 출력 후에만 checkpoint·복구 완료·보관 정리를 수행한다.
- `recording_continuity.py`는 `recovery_snapshot`과 `buffer_status`를 허용 목록으로 처리한다. `observed_at`/`lookup_at`은 실행·조회 시각, `window_from/window_to/target`은 미디어 시각이다. CDN·mode·role·result·lookup_result는 열거형, elapsed/개수/용량은 범위 검증, 목록 시간 범위는 순서 검증을 적용한다. 조회 결과는 해당 Manifest에 묶어 같은 CDN의 다른 목록 결과와 섞이지 않게 했다. 복구 시작·완료·전환은 즉시, 대기 진단은 CDN/역할/방식별 5초 간격이다.
- 같은 CDN의 대체 준비와 다른 CDN의 예비 준비를 `independent_cdn`으로 구분하고 경고·정리 실패 안내를 포함해 `i18n.py` 다섯 언어를 갱신했다. 기존 `source` 이벤트도 읽는다.
- `continuity_report.py`의 시작 행은 `plugin/chzzk.py`, `hls_continuity.py`, `recording_buffer.py`의 SHA-256을 포함한다. 기존 해시 없는 보고서도 읽으며 공백·중복·미해결 전환·불완전 보고서 판정은 바꾸지 않았다. Actions 파일의 5분 분할·영상 정리는 수정하지 않았다.

## 검증

- 설치된 Streamlink 8.6.2의 실제 worker/writer/reader 및 로컬 HTTP CDN으로 장애를 주입했다. 로컬 서버 개설이 샌드박스에서 제한되어 해당 테스트는 승인된 외부 실행으로 수행했다. 원격 실방송에 접속하거나 Actions를 실행하지 않았다.
- 기존 91개 검사는 초기 구현에서 통과했다. 확장 검사는 주소/메타데이터 보존, 꽉 찬 출력 대기열, 대체 목록 후속 보관, 디스크 인계 뒤 원격 404, 손상 및 쓰기 실패, 시간·용량 한도, 방송/화질 격리, 다운로드 중 중지, 안전한 진단 및 번역을 포함한다.
- 최종 `.venv/bin/python -m unittest discover -s tests -v`: **106개 모두 통과**, 59.269초. 결과는 `/tmp/chzzk-buffer-final-106-tests.log`에 있다. 합성 장애 검사의 누락·중복 0과 영구 누락의 정확한 실패 판정을 확인했으며 실방송 결과로 일반화하지 않는다.
- 회귀 검사 중 보관 위치만 선택해 최신 후속 조각이 빠지는 문제, 중복 후보 주소의 재시도, 조회 전 진단 기본값 누락을 발견해 수정했다.
- 실제 FFmpeg fixture는 영상 1,000프레임을 가진 fMP4와 AAC 음성이다. 일시 장애/정상 전환은 500+500프레임과 음성 수·PTS를 검사한다. 영구 누락/디스크 인계는 250+500프레임과 음성 수·PTS, 공백 한 번 및 250/60초 길이를 검사한다. 후속 조각의 원격 주소를 404로 바꾼 뒤에도 새 자식이 보관된 500프레임을 모두 출력하는 사례를 포함한다.
- 변경한 Python 8개 파일의 문법 컴파일과 `git diff --check`도 통과했다.

## 남은 검증과 제한

국내 VPS/해외 실방송 장기 녹화, Windows/macOS의 파일 잠금·정리 동작은 이번 로컬 검사로 확정하지 않았다. 강제 종료 후 영구 복원은 범위 밖이다. 이미 조회·수신하지 못한 조각, 보관 한도를 벗어난 후속 조각이나 모든 CDN에서 영구 소실된 데이터는 복원할 수 없다. 해외 무손실을 선언하지 않으며 다음 장기 검사에서 새 snapshot 및 코드 해시로 원인을 구분한다. 커밋·push·원격 Actions 실행은 하지 않았다.

## 로컬 커밋 요청

- 같은 날 사용자가 로컬 커밋을 요청했다. 구현·테스트·다국어 안내와 승인 계획/검증 기록, 이번 개선의 근거인 국내 VPS/해외 비교 및 CDN/PART 후속 분석 기록을 함께 커밋 대상으로 확인했다.
- 직전 전체 106개 테스트 통과 로그와 현재 변경 목록을 재확인했다. 실행 코드는 추가로 수정하지 않았으며 whitespace 검사를 다시 수행했다. push·원격 Actions 실행은 요청 범위에 포함하지 않는다.
