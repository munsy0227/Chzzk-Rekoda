# 지침 정리, 작업 메모 규칙 및 Qt GUI 검토

## 요청

- 흩어진 작업 지침을 `.ai/`에 모으기.
- 이후 매 작업마다 `.ai/`에 다음 작업을 돕는 메모 남기기.
- Qt 기반 GUI의 구현 방향 검토.

## 실제 수행

- 기존 `AGENTS.md`, `codex.md`를 `.ai/`로 옮기고 루트 `AGENTS.md`를 안내 파일로 바꿨다. 이동 직후 두 파일이 원본과 바이트 단위로 같은지 확인했다.
- 후속 요청에 따라 `.ai/AGENTS.md`에 작업 시작 시 관련 메모를 읽고, 종료/인계 시 작업 내역을 기록하는 규칙을 추가했다.
- `.ai/KNOWLEDGE.md`에 현재 구조와 메모 위치를 정리하고 루트 안내 파일에서 연결했다.
- `settings.py`, `chzzk_record.py`, `i18n.py`, `pyproject.toml`, `README.md`를 읽고 [GUI 제안](../plans/qt-gui.md)을 작성했다.
- 확인 시 브랜치는 `main`, HEAD는 `f6e3e53`이었다. 지침 이동 변경은 이미 작업 트리에 있었으며 그대로 이어서 정리했다.

## 판단과 근거

- `settings.py`의 최상위 `load_config()`와 메뉴 루프는 GUI에서 직접 import하기 어렵게 하므로 설정 처리 분리를 먼저 제안한다.
- 녹화기는 asyncio, 전역 상태, Rich 화면을 함께 사용하므로 첫 GUI에서는 별도 프로세스 실행과 명령/이벤트 연결을 제안한다.
- 기존 `load_config_async()`의 마지막 유효 설정 유지, 종료 후 로그 처리 경로를 현재 코드에서 확인했다. GUI 연결 시 보존해야 한다.
- Qt 공식 문서에서 PySide6 및 QProcess를 확인했다. GUI의 정상 종료는 명시적인 중지 명령으로 처리하는 방향을 제안 문서에 남겼다.

## 검증과 다음 작업

- 지침 이동 단계: 원문 보존, 안내 링크 존재, whitespace 검사 및 `git diff --check` 통과.
- 메모 추가 단계: Markdown 6개 파일의 UTF-8 읽기, 마지막 개행, trailing whitespace 및 내부 링크 8개를 확인했고 `git diff --check`도 통과했다.
- Python 코드와 의존성은 변경하지 않았다. GUI 실행, 실제 녹화, 플랫폼별 동작은 이번 작업에서 검증하지 않았다.
- 다음 시작점: GUI 제안의 우선순위를 사용자와 정한 뒤 공용 설정 처리 분리부터 진행한다. 현재 제안은 사용자 확정 설계나 구현 완료 사항이 아니다.
