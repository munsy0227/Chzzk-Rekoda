## 우선 수정할 실제 오류

### 1. [P2, 기존 문제] 방송 종료 통지가 진행 중인 정상 미디어 수신을 중단한다

- 역할: `hls_continuity.py:ChzzkContinuityWriter._fetch()`는 원래 조각 요청이 2초 지연되면 예비 경로와 API 조회를 병행한다.
- 문제: `hls_continuity.py:1566-1576`은 API 종료 상태나 예비 조회의 `BroadcastEnded`를 즉시 올린다. 원래 요청이 아직 진행 중이어도 기다리지 않는다. `run():1778-1780`은 이를 받아 종료 경계로 닫으며, `_fail():1638-1639`는 종료 이유일 때 재개 위치를 없앤다. 따라서 방송 종료 직전의 정상 조각을 놓칠 수 있다. PR #88이 새로 만든 문제는 아니다.
- 실제 메서드 재현: Python 3.12.16 / 잠금 Streamlink 8.6.2 및 기존 `tests/test_hls_continuity.py:CDN`을 사용했다. 정상 후보를 먼저 읽고 API 갱신 시각을 만료시킨 뒤 provider만 종료 응답으로 바꿨다. 마지막 조각 27바이트를 0.1초마다 한 바이트씩 보내고, 요청 시간 제한은 10초로 설정했다. 제품의 `HEDGE_DELAY=2.0`은 그대로 유지했다.
- 결과: `_fetch()`는 2.001초에 `BroadcastEnded`를 올렸고 원래 요청은 진행 중이었다. 같은 요청을 관찰하자 2.605초에 성공했으며 결과 미디어가 원본 `MEDIA[-1]`와 정확히 일치했다. 외부 방송이나 실제 녹화 파일의 누락을 측정한 결과는 아니다.
- 종료 후 재시도·보고서 연결 확인: `/tmp/chzzk-pr88-tail-repro.py`는 실제 소스 AST에서 `_fetch/run/fail/_fail/boundary`와 API 갱신 메서드를 추출하고 입출력만 합성한다. 지정 Python 3.12 환경에서 API 종료 2.002초 → writer 종료 2.052초(원래 요청 진행 중) → 원래 요청 성공 2.252초를 확인했다. 실제 `RecordingContinuity.accept()`의 재개 위치는 `None`이 됐다. 앞선 정상 checkpoint와 종료 경계·완료 footer를 실제 `continuity_report.summarize()`에 넣은 합성 보고서는 `passed=true`, gap/unresolved/error 각각 0이었다. 실방송 영상이나 실제 수신 영상 전체의 판정을 대신하지 않는다.
- 최소 수정: API 종료는 새 경로 탐색을 끝내는 신호로 처리하되 이미 알고 있는 조각의 진행 중 요청은 정해진 예산 안에서 회수하고 출력한 뒤 종료한다. 같은 시점 경쟁을 고정하는 회귀 테스트를 기존 HLS 테스트에 추가한다. 새 방송의 조각을 섞지 않도록 방송 ID 검증은 유지해야 한다.
- 미수정 영향: 느린 네트워크에서 방송 마지막 부분이 정상 종료처럼 잘릴 수 있다. 보고서의 `broadcast_ended` 처리가 누락 검증을 대신하지 않으므로 전체 테스트 통과나 정상 종료만으로 꼬리 보존을 확정하지 않는다.

### 2. [P2, PR 연결 경로] 마법사와 이후 채널 추가가 폴더 끝 공백을 다르게 처리한다

- 역할: 마법사에서 채널별 폴더와 이후 새 채널의 기본 루트를 결정한다.

- 미수정 영향: 같은 기본 저장 위치를 지정했는데 등록 시점에 따라 녹화가 서로 다른 폴더에 쌓일 수 있다.

## 사용자 요청에 따른 두 오류 수정

- 사용자 요청: 검토에서 확인한 두 오류를 모두 수정한다. 추가로 폴더 선택창에서 실제 `test ` 폴더가 생기는 상황을 알렸고, 끝 공백이 있는 폴더를 선택하면 **경고하고 다시 선택하도록 하기**를 명시적으로 선택했다.
- `hls_continuity.py:ChzzkContinuityWriter._fetch()`는 API 종료를 진행 중인 다운로드 실패로 취급하지 않는다. 이미 시작한 요청과 확보한 예비 후보를 계속 처리하며, 종료 뒤 새 API·CDN·토큰 탐색은 막는다. 알려진 URL의 재시도는 기존 복구 기한을 유지한다. 끝내 실패하면 일반 미해결 경계로 남겨 정상 종료/성공 보고서로 숨기지 않는다. 방송 ID 변경과 사용자 중지의 중단 경로는 유지했다.
- 연결된 `ContinuitySource.between()` 및 `repair_chain()`도 종료 후 이미 관측·보관한 후보를 검증·출력할 수 있게 했다. 새 탐색은 수행하지 않으며 필요한 중간 조각이 없으면 기존 복구 기한 뒤 미해결로 남긴다.
- `gui/settings_dialog.py:validate_output_directory()`를 마법사와 채널 편집에서 공유한다. 경로 각 폴더명 앞뒤에 공백이 있으면 경고하고 선택·채널 추가·완료·저장을 거절한다. 하위 폴더나 끝 구분자로 검증을 우회하지 못한다. 입력 문자열을 잘라 다른 실제 경로로 바꾸지 않으며, 생성된 폴더의 이름·내용을 변경하거나 삭제하지 않는다. 한글·이름 내부 공백·`~`·상대경로는 유지했다.
- `i18n.py`에 경고를 한국어·영어·중국어 간체·중국어 정체·일본어로 함께 추가했다. OS/Qt가 담당하는 폴더 생성 자체는 변경하지 않았다.

- 수정 후 지정 Python 3.12.16 / 잠금 Streamlink 8.6.2에서 전체 unittest **137개 통과**, 테스트 시간 84.681초. 출력은 `/tmp/chzzk-pr88-fixes-unittest.log`에 있다. 방송 관련 집중 검사 9개도 통과했다.
