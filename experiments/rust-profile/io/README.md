# Rust I/O profile

This experiment stays outside the recorder. It compares the production Python
`MediaBuffer` and `BufferedDownload.materialize()` with a Rust raw-file copy,
the production `pipe_stream_to_stdin()` with a Rust stdin/stdout relay and a
direct OS pipe, and Python segment enumeration/size measurement with Rust scan,
sort, stat, and sum. It also compares SHA-256 over separate init/media buffers:
Python's existing `hashlib.sha256(init + media)`, two `update()` calls, and a
Rust `sha2` batch. Rust reports each in-process hash duration separately from
child process wall time, which includes startup and file reads.

Build with the isolated toolchain and target directory, then run the quick
correctness pass or the full workload:

```sh
export CARGO_HOME=/tmp/chzzk-rust-cargo
export RUSTUP_HOME=/tmp/chzzk-rust-rustup
export PATH=/tmp/chzzk-rust-cargo/bin:$PATH
cargo build --release --manifest-path experiments/rust-profile/io/Cargo.toml \
  --target-dir /tmp/chzzk-profile-io-target
/tmp/chzzk-rust-env/bin/python experiments/rust-profile/io/bench.py --quick
/tmp/chzzk-rust-env/bin/python experiments/rust-profile/io/bench.py --full \
  --output /tmp/chzzk-rust-io-results.json
```

The full run uses 1 and 8 MiB buffer payloads on `/tmp` (tmpfs on the measured host) and this experiment's
`.cache` directory, three pipe paths at 256 MiB (three repeats each), and
100/1,000/10,000 segment files. All files are temporary and removed. The Rust
relay's producer, relay, and sink are linked through OS file descriptors; no
Python pump sits in that path. Results include per-repeat wall/process/child
CPU, RSS high-water metadata, separate traced Python allocation passes,
environment metadata, and raw timings. The filesystem cache is warm; no
privileged cache flush is attempted.

The Rust buffer case is deliberately labeled raw I/O: it does not implement
`MediaBuffer` validation, locks, SHA-256, metadata, limits, or eviction. Its
copy integrity check uses CRC-32; the Python comparison uses the same checksum.
Rust uses the `crc32fast` crate so checksum work uses a native optimized library.
Pipe CRC-32/count and child exit status must match for every path. Rust segment
matching covers the ASCII decimal filenames generated by the recorder and
rejects malformed or nonmatching names; Python's `\d` also accepts Unicode
decimal digits, which are outside this comparison domain. The cached Python
size row is a stable-directory snapshot and has no invalidation logic. The slow
consumer cases check backpressure and EOF completion for Python and Rust. The
`MediaBuffer.store` timing reuses a prebuilt object, metadata, and payload; it
times the `store()` call only. Python
`recording_output_size` is compared with Rust scan, sort, stat, and sum over
temporary files, including empty and renamed matching files.
